==================================================
PHASE M OBJECTIVE
==================================================

Create growth automation that helps users return when something relevant happens.

Potential triggers:

- Saved search match
- New matching listing
- Price drop
- Unread message reminder
- Pending offer reminder
- Listing expiration reminder
- Relist reminder
- Delivery update
- Seller activity summary
- New nearby inventory
- Saved item activity
- Buyer/seller follow-up

Every notification must be based on real marketplace events.

==================================================
1. NOTIFICATION PREFERENCE CENTER
==================================================

Create or improve user notification preferences.

Potential controls:

Saved Search Matches
Price Drops
Messages
Offers
Listing Expiration
Relist Reminders
Delivery Updates
Seller Performance
Marketplace Recommendations

Channels:

In-App
Email

No SMS.

Users should be able to turn non-essential notifications off.

==================================================
2. SAVED SEARCH ALERTS
==================================================

Reuse the Saved Search foundation from Phase E/K.

Flow:

User saves search
→ new listing published
→ Phase F worker matches search
→ user receives notification

Example:

“New Toyota Camry listed under $18,000 near you.”

Only send when the listing actually matches.

Prevent duplicate notifications.

==================================================
3. PRICE DROP ALERTS
==================================================

If a user saved a listing:

Listing price changes downward
→ create price-drop alert

Example:

“Price dropped from $10,000 to $9,500.”

Use actual stored price history/current values.

Do not invent previous pricing.

Do not notify if price increased.

==================================================
4. UNREAD MESSAGE REMINDERS
==================================================

If a user has unread buyer/seller messages:

Create a reminder after an appropriate delay.

Do not repeatedly notify every few minutes.

Use sensible deduplication and cooldown rules.

Example:

“You have an unread message about your Chevrolet Volt.”

Do not include unnecessary private message content in email subject lines.

==================================================
5. OFFER REMINDERS
==================================================

For pending marketplace offers:

Seller:
“You have 2 pending offers.”

Buyer:
“Your offer is still awaiting a response.”

Avoid excessive reminders.

Do not automatically accept/decline offers.

==================================================
6. LISTING EXPIRATION REMINDERS
==================================================

Before an active listing expires:

Send an in-app reminder.

Optional email if enabled.

Example:

“Your listing expires in 3 days.”

Use actual expiration rules.

==================================================
7. RELIST REMINDERS
==================================================

If a listing expires or becomes inactive under existing marketplace rules:

Offer:

Relist

Do not automatically relist without seller confirmation.

If strict abandoned-draft deletion rules apply, preserve them.

==================================================
8. SOLD LISTING BEHAVIOR
==================================================

Do not send:

- expiration alerts
- relist alerts
- price-drop alerts

for sold listings unless a specific seller action makes sense.

==================================================
9. DELIVERY UPDATES
==================================================

Use actual JHE Haul delivery states.

Potential notifications:

Delivery requested
Driver/hauler assigned
Scheduled
Picked up
Delivered
Issue requiring attention

Do not invent delivery status.

Do not expose private addresses in unnecessary notification content.

==================================================
10. SELLER PERFORMANCE ALERTS
==================================================

Reuse Phase I Seller Intelligence.

Examples:

“Your listing has received 50 views.”

“You have 3 unanswered messages.”

“Your listing has strong activity.”

“Your listing may need attention.”

Use real data only.

Do not over-notify for every view.

==================================================
11. NEW NEAR YOU
==================================================

Where personalization is enabled:

Periodically surface meaningful new inventory near a user.

Use:
- general location
- saved interests
- search activity
- marketplace category interest

Do not send generic daily spam.

Only notify when relevance is high enough.

==================================================
12. RECOMMENDATION RE-ENGAGEMENT
==================================================

Reuse Phase K RecommendationService.

Potential message:

“New vehicles similar to ones you viewed are available.”

Do not reveal private browsing history in a way that feels invasive.

Keep notification wording general.

==================================================
13. NOTIFICATION DEDUPLICATION
==================================================

Critical:

Do not repeatedly send the same alert.

Create deduplication rules using:

user
event type
listing/resource
time window

Example:

Same price drop
→ one notification

Same saved-search match
→ one notification per matched listing

==================================================
14. COOLDOWNS
==================================================

Implement cooldown periods.

Examples:

Unread message reminder
→ not every hour indefinitely

Seller performance reminder
→ limited frequency

Recommendation alert
→ limited frequency

Do not create notification fatigue.

==================================================
15. PRIORITY
==================================================

Classify notifications.

Potential levels:

URGENT
IMPORTANT
NORMAL
LOW

Examples:

URGENT:
Account/security issue
Critical delivery issue

IMPORTANT:
Offer received
Unread buyer message
Delivery update

NORMAL:
Saved search match
Price drop

LOW:
Marketplace recommendation

Do not abuse high-priority classifications.

==================================================
16. IN-APP NOTIFICATION CENTER
==================================================

Ensure users have a clean notification center.

Support:

Unread

Open related listing/message/delivery

Keep alerts concise.

==================================================
17. EMAIL
==================================================

Use SendGrid or the existing email system.

- saved search matches
- price drops

- listing expiration
- delivery updates

==================================================
18. SENDGRID FAILURE SAFETY
==================================================

Because prior SendGrid delivery problems existed, growth automation must not assume email always works.

Flow:

Notification event
→ create in-app notification
→ enqueue email separately
→ email failure logged
→ in-app notification remains available

Email failure must not break marketplace action.

==================================================
19. EMAIL RETRIES
==================================================

Reuse Phase F queue.

Temporary SendGrid/network failure:
→ retry safely

Permanent delivery failure:
→ stop retrying after limit

Prevent duplicate emails.

==================================================
20. UNSUBSCRIBE / PREFERENCES
==================================================

Non-essential marketing/recommendation emails must respect user preferences.

Provide a clear preference-management path.

Do not disable transactional/security email merely because marketing preferences are off.
