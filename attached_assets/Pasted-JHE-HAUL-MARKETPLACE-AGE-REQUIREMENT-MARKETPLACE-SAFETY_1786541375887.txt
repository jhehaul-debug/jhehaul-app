JHE HAUL MARKETPLACE — AGE REQUIREMENT, MARKETPLACE SAFETY, FRAUD PROTECTION, REPORTING, AND MEDIA UPLOAD LIMITS

Add the following requirements to the EXISTING JHE Haul Marketplace reconstruction.

IMPORTANT:

These requirements apply to the NEW JHE HAUL MARKETPLACE where users list items for sale, buyers browse listings, buyers and sellers communicate, offers are made, and JHE Haul delivery may be requested.

These requirements are NOT for the old hauling/job-bidding system.

Do NOT rebuild the application from scratch.

Preserve the existing:

* User accounts
* Authentication
* Admin system
* Database
* Marketplace work already completed
* Stripe integration
* Email integration
* Twilio integration
* GitHub repository
* DigitalOcean deployment
* Environment variables
* Existing working functionality

Use safe database migrations when database changes are required.

Do not delete old production data.

==================================================

1. ACCOUNT AGE REQUIREMENT — 18+
    ==================================================

A person must be at least 18 years old to create a JHE Haul Marketplace account.

During account registration, prominently display:

“I certify that I am at least 18 years old.”

Require the user to actively check the checkbox before account creation can continue.

DO NOT pre-check this box.

If the user does not confirm that they are at least 18 years old:

ACCOUNT CREATION MUST NOT CONTINUE.

Implement appropriate client-side AND server-side validation so the requirement cannot simply be bypassed through a direct API request.

Include the 18+ requirement in:

* Registration
* Terms of Use
* Marketplace Rules
* Marketplace Safety information

Prepare the architecture so stronger age-verification methods could be added later if required.

Do NOT unnecessarily collect driver’s licenses, Social Security numbers, or other sensitive identity documents merely to implement the basic 18+ confirmation.

2. MARKETPLACE SAFETY WARNING

Create clear marketplace safety warnings telling users to watch for:

* Fraud
* Scams
* Fake listings
* Stolen property
* Counterfeit merchandise
* Misrepresentation
* Payment scams
* Phishing
* Identity-theft attempts
* Suspicious links
* Requests for passwords
* Requests for verification/security codes
* Requests for banking login information
* Suspicious payment methods
* Harassment
* Threats
* Other suspicious or criminal activity

Use clear language similar to:

“Stay alert for fraud, scams, and criminal activity. Never send passwords, verification codes, banking login information, or other sensitive personal information to another marketplace user.”

Also communicate:

“JHE Haul Marketplace cannot guarantee the identity, honesty, ownership claims, or intentions of every buyer or seller. Use good judgment and report suspicious activity.”

Do not represent JHE Haul as guaranteeing the legitimacy or safety of every transaction.

3. MARKETPLACE SAFETY PAGE

Create a dedicated:

MARKETPLACE SAFETY

page.

Include practical safety guidance.

Examples:

* Inspect an item before paying whenever practical.
* Meet in a safe public location when appropriate.
* Be cautious of prices that appear unrealistically low.
* Never provide another user with your password.
* Never provide another user with account verification codes.
* Never provide banking login credentials.
* Be cautious about clicking suspicious links.
* Be cautious when someone pressures you to act immediately.
* Be cautious when someone requests unusual payment arrangements.
* Report suspicious listings and users.
* Keep important marketplace communication inside JHE Haul when practical so there is a record of the conversation.
* Trust your judgment if a transaction appears suspicious.
* If there is an immediate threat or emergency, contact appropriate emergency services directly.

Do not imply that JHE Haul replaces law enforcement.

10. MEDIA LIMITS — PER MARKETPLACE LISTING

Each individual marketplace listing may contain a MAXIMUM of:

20 PHOTOS

AND

1 VIDEO

The ONE video may be a MAXIMUM OF:

60 SECONDS

These limits apply PER LISTING.

They do NOT mean that a seller can only upload 20 photos across their entire account.

A seller with multiple listings can upload media separately for each listing, subject to the limits for each individual listing.

==================================================
11. PHOTO LIMIT

Allow a maximum of:

20 PHOTOS PER LISTING

Display an upload counter such as:

Photos: 0 / 20

Photos: 8 / 20

Photos: 20 / 20

Once 20 photos have been uploaded:

Do not allow another photo.

Display:

“You can upload up to 20 photos per listing.”

A 21st photo must be rejected.

==================================================
12. PHOTO MANAGEMENT

Allow sellers to:

* Take photos from a supported mobile device
* Select existing photos
* Upload photos
* Preview photos
* Reorder photos
* Delete photos
* Replace photos
* Select a primary/cover photo

The primary photo should appear on the marketplace listing card.

Optimize marketplace images for reasonable performance while maintaining useful visual quality.

==================================================
13. VIDEO LIMIT

Allow:

1 VIDEO PER LISTING

Maximum runtime:

60 SECONDS

Display clearly during listing creation:

“1 video maximum — up to 60 seconds.”

If the user attempts to upload another video:

Reject the second video.

Display:

“You can upload one video per listing.”

==================================================
14. 60-SECOND VIDEO VALIDATION

The marketplace must NOT accept a listing video longer than 60 seconds.

If a seller attempts to upload a video exceeding 60 seconds, display:

“Videos must be 60 seconds or less.”

Validate the video duration:

CLIENT-SIDE where technically appropriate

AND

SERVER-SIDE

Do not rely solely on the browser/app interface.

A user must not be able to bypass the 60-second limit through a direct API request.

==================================================
15. VIDEO MANAGEMENT

Allow sellers to:

* Upload one video
* Select a video from their device
* Preview the video
* Remove the video
* Replace the video

Do not allow multiple videos during Phase 1.

Optimize/compress video where technically appropriate while maintaining reasonable marketplace viewing quality.

16. VIDEO FILE-SIZE LIMIT

In addition to the 60-second runtime limit, determine a reasonable maximum VIDEO FILE SIZE based on the application’s existing:

Do NOT create a storage-heavy configuration that risks production stability or unexpectedly high infrastructure costs.

18. SERVER-SIDE UPLOAD SECURITY

Media restrictions must be enforced SERVER-SIDE.

Do not rely exclusively on client-side validation.

Verify:

* User authentication
* Listing ownership
* File type
* MIME type
* File size
* Image count
* Video count
* Video runtime

Prevent users from bypassing:

20-photo maximum

1-video maximum

60-second video maximum

through direct API requests.

Use safe filenames/storage identifiers.

Do not execute uploaded files.

==================================================
19. MEDIA OWNERSHIP SECURITY

A user must NEVER be able to:

* Add media to another user’s listing
* Delete another user’s listing media
* Replace another user’s listing media
* Reorder another user’s listing photos
* Change another user’s cover photo

Verify listing ownership before media modifications.

Admin access should follow existing authorized admin rules.
