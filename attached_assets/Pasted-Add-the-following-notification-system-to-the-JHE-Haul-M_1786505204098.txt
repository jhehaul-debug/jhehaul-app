Add the following notification system to the JHE Haul Marketplace reconstruction.

IMPORTANT:

These notifications are for the NEW JHE HAUL MARKETPLACE where users list items for sale.

Do NOT build notifications around the old hauling-job bidding system.

The notification system should be designed around:

* Marketplace listings
* Buyer/seller messages
* Offers
* Counteroffers
* Sold/reserved listings
* JHE Haul delivery requests
* Delivery quotes
* Account and admin notices

========================================
PRIMARY NOTIFICATION METHOD

Build IN-APP NOTIFICATIONS as the primary notification system.

Do NOT require paid SMS in Phase 1.

Use email only for important marketplace activity where appropriate.

The system should work even if SMS/Twilio is disabled.

========================================
NOTIFICATION BELL

Add a notification bell to the logged-in interface.

The bell should display an unread-count badge.

Examples:

🔔 1
🔔 3
🔔 12

When the user taps the bell, open:

Notifications

Notifications should appear newest first.

Each notification should display:

* Notification icon
* Short title
* Short description
* Time/date
* Read/unread state

Unread notifications should be visually distinct.

========================================
CLICKABLE NOTIFICATIONS

Notifications must link directly to the relevant marketplace activity.

Examples:

New message
→ Open the correct conversation

New offer
→ Open the offer and listing

Counteroffer
→ Open the offer

Offer accepted
→ Open listing/offer details

Delivery quote ready
→ Open delivery request

Listing reported
→ Admin moderation screen

Do not send users to a generic page when a specific destination is available.

========================================

Create notification support for:

NEW MESSAGE

Example:

“New message about your sofa”

“You received a message from a buyer.”

⸻

“Someone made an offer on your listing.”

⸻

COUNTEROFFER RECEIVED

“Seller countered at $225”

⸻

OFFER ACCEPTED

⸻

OFFER DECLINED

“Your offer was declined.”

⸻

⸻

⸻

“An item you saved has sold.”

Renew Listing

Allow administrators to send important account or marketplace notices.

Examples:

========================================
NOTIFICATION DATABASE

Create or safely adapt a notifications table/model.

Recommended fields:

notification_id

user_id

type

title

message

related_listing_id

related_offer_id

related_conversation_id

related_delivery_request_id

related_user_id

action_url or destination information

is_read

created_at

read_at

metadata when needed

Do not store unnecessary sensitive information inside notification text.

========================================
READ / UNREAD

Support:

Mark notification as read

Mark notification as unread

Mark all as read

Unread count

When the user opens a notification, it should normally become read.

Do not delete notifications simply because they are read.

========================================
NOTIFICATION PAGE

Create a full Notifications page.

Include filters if appropriate:

All
Unread
Messages
Offers
Listings
Delivery
Account

Keep the mobile version simple.

========================================
EMAIL NOTIFICATIONS

Where existing email infrastructure is available, use email for IMPORTANT marketplace events.

Recommended email alerts:

* New buyer inquiry/message
* Offer accepted
* Important counteroffer
* Delivery quote ready
* Account verification
* Password reset
* Important admin/moderation notice

Avoid sending unnecessary emails for every minor marketplace action.

Prevent email flooding.

Where practical, allow users to control email notification preferences later.

========================================
EMAIL PREFERENCES

Prepare support for notification settings such as:

In-App Notifications:
ON by default

Email — Messages:
ON/OFF

Email — Offers:
ON/OFF

Email — Delivery:
ON/OFF

Email — Account/Security:
Required where appropriate

Marketing Email:
Separate opt-in

Do not treat required transactional/security emails as marketing emails.

========================================
SMS

Do NOT make SMS a requirement in Phase 1.

Preserve existing Twilio functionality if it already exists.

Do not delete Twilio configuration.

However:

Marketplace notifications should work fully using:

1. In-app notifications
2. Email

SMS can be added later as an optional paid/premium feature if desired.

========================================
REAL-TIME EXPERIENCE

Where the current technology stack safely supports it, notifications should update promptly after events occur.

Examples:

Buyer sends message
→ Seller receives notification

Buyer makes offer
→ Seller receives notification

Seller accepts offer
→ Buyer receives notification

Admin enters delivery quote
→ Customer receives notification

Do not introduce unstable infrastructure solely for real-time behavior if a reliable polling/refetch system is more appropriate for the existing application.

========================================
MOBILE DESIGN

The notification system must be mobile-first.

Notification rows should be easy to tap.

Use clear icons for:

Messages
Offers
Listings
Delivery
Admin

Unread notifications should be obvious without making the interface cluttered.

========================================
ADMIN NOTIFICATIONS

Admin dashboard should surface:

New delivery requests

Reported listings

Reported users

New moderation issues

Delivery quotes awaiting action

Other marketplace issues requiring attention

These can appear in an admin notification center or dashboard alert system.

========================================
SECURITY

A user must NEVER be able to access another user’s private notification.

Every notification endpoint must verify ownership.

Do not expose:

Private messages

Addresses

Private contact information

Admin-only data

through notification previews unless the user is authorized to see it.
