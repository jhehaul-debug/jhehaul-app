JHE HAUL — PHASE E
AI SEARCH INTELLIGENCE

Phase D is complete and verified live.

Now begin Phase E.

This phase introduces intelligent marketplace search.

Do NOT begin the full AI Copilot yet.

Do NOT build autonomous AI agents yet.

Do NOT remove or replace normal marketplace search.

AI Search should ADD intelligence to the existing search system while preserving normal search and filters.

IMPORTANT:

Do not change anything else.
Do not break any other working features.
Keep all unrelated functionality exactly as it is.

==================================================
PHASE E OBJECTIVE

Allow buyers to search JHE Haul using normal conversational language.

Examples:

“Find me a reliable SUV under $15,000 within 30 miles.”

“Show me refrigerators under $500 near Maplewood.”

“Find me a Toyota Camry from 2018 to 2023.”

“Show me furniture that JHE Haul can deliver.”

“Find a car under $10,000 with less than 120,000 miles.”

“Show me recently listed appliances.”

The system should understand the request and translate it into safe marketplace search parameters.

==================================================

    ==================================================

Preserve the existing:

* Search box
* Keyword search
* Categories
* Price filters
* Condition filters
* Location
* Distance/radius
* Vehicle filters
* Delivery filters
* Sort controls

If AI Search fails or is unavailable:

NORMAL SEARCH MUST STILL WORK.

2. ADD “ASK JHE HAUL” SEARCH

Add an optional AI-assisted search entry point.

Potential interface:

Search marketplace…

and a secondary option:

✨ Ask JHE Haul

or:

“Describe what you’re looking for”

Example placeholder:

“Find me a used SUV under $15,000 within 25 miles”

Keep the interface simple on mobile.

==================================================
3. NATURAL-LANGUAGE QUERY PARSING

Create a backend search-intelligence service that converts natural-language requests into structured search parameters.

Example:

User:

“Toyota Camry under $18,000 from 2018 or newer within 50 miles.”

AI output should become structured data similar to:

category = Vehicles
make = Toyota
model = Camry
min_year = 2018
max_price = 18000
radius = 50 miles

Then the EXISTING backend search system should execute the actual query.

Do NOT let the AI directly query unrestricted production data.

==================================================
4. STRUCTURED AI OUTPUT

Require the AI to return a strict structured format.

Example concept:

{
“keywords”: [],
“category”: null,
“min_price”: null,
“max_price”: null,
“condition”: [],
“location”: null,
“radius_miles”: null,
“vehicle”: {
“year_min”: null,
“year_max”: null,
“make”: null,
“model”: null,
“mileage_max”: null
},
“delivery_available”: null,
“sort”: null
}

Validate every field server-side.

Never trust raw AI output.

==================================================
5. SEARCH TOOL LAYER

AI should NOT receive direct unrestricted database access.

Create a controlled function/service such as:

search_marketplace(filters)

The backend should:

1. Validate filters.
2. Apply user permissions.
3. Apply marketplace rules.
4. Query only ACTIVE/public listings.
5. Return safe public listing information.

==================================================
6. SEARCH RESULT PRIVACY

AI Search must never expose:

* Seller email
* Seller phone
* Exact private address
* Private messages
* Offers
* Payment data
* Internal admin data
* Private delivery locations
* Sensitive user identifiers

Use only information that normal marketplace buyers are authorized to see.

==================================================

Year

8. CATEGORY SEARCH

AI should map conversational terms to existing marketplace categories where reasonable.

Examples:

“couch”
→ Furniture

“fridge”
→ Appliances

“car”
→ Vehicles

“restaurant fryer”
→ Restaurant Equipment

Do not create categories automatically.

Use the existing configured category system.

==================================================
9. LOCATION INTELLIGENCE

Support searches using general public locations.

Example:

“within 25 miles of Maplewood”

Use the existing location/radius infrastructure where available.

Do NOT send or expose a user’s exact private home address to the AI provider.

Where appropriate, use city/ZIP or coordinates through existing backend logic.

==================================================
10. DELIVERY SEARCH

Support search intent such as:

“Show me items JHE Haul can deliver.”

Filter based on actual delivery availability.

Do not claim delivery is available when the listing does not support it.

==================================================
11. RECENCY SEARCH

Support searches such as:

“listed today”

“added this week”

“newest furniture”

Use actual published timestamps.

Do not use abandoned/draft listing timestamps.

==================================================
12. RESULT EXPLANATION

Where useful, AI Search may show a small interpretation summary.

Example:

Searching for:

Toyota Camry
2018 or newer
Under $18,000
Within 50 miles

Allow the user to edit/remove interpreted filters.

This gives users control over what the AI understood.

==================================================
13. NO RESULTS

If no listings match:

Do not invent results.

Show:

“No matching listings found.”

Offer useful actions such as:

* Expand distance
* Increase price
* Remove a filter
* Save this search

Prepare for saved searches where appropriate.

==================================================
16. AI PROVIDER

Reuse the approved AI provider/service architecture from Phase D.

Do not add another AI provider unless there is a clear technical reason.

Never expose the AI API key in frontend code.

==================================================
17. COST CONTROL

AI Search can generate many requests.

Implement:

* rate limiting
* input length limit
* request timeout
* output-token limit
* safe retry behavior
* usage logging
* caching where appropriate

If the exact same user search is repeated, consider reusing a recent parsed result rather than unnecessarily calling AI again.

==================================================
18. PROMPT-INJECTION DEFENSE

Treat the buyer’s search text as untrusted input.

The buyer query must never be allowed to:

* change AI system instructions
* request secret data
* access other users’ private records
* bypass marketplace permissions
* execute arbitrary tools
* access Admin functionality

AI Search should only perform marketplace-search interpretation.

* popular price ranges

Use aggregate data responsibly.

Do not expose individual private search histories to unrelated users.
